# 参考规格书（Reference Spec）：先写清「要还原什么」，再动手建模

> 本文件治的是另一类失败：**表面相似**。
> 上一类失败（2026-11-11 那次「占比全 PASS 却被判很差」）是**门禁失效**，
> 处方在 `visual-parity.md`。这一份治的是：形状大致对了、颜色大致对了，
> 但结构站不住、细节撑不住、离近看就散——因为它只是照着单张图描了一遍轮廓。

## 0. 单张图的信息上限

一张参考图只能提供「这一个视角、这一种光、这一层遮挡」的投影结果。它不含：

| 缺失信息 | 后果 | 本文件的解法 |
|---|---|---|
| 背面 / 侧面 / 底面 | 相机一转就露馅，或干脆锁死相机不敢给交互 | 0B 检索多角度参考，或明确声明「背面为补建」 |
| 真实尺寸与比例 | 桌高 0.6 还是 0.9 全靠猜，家具之间比例链断裂 | 用人体/常规器具反推尺度链（§3.4） |
| 结构连接方式 | 悬空、穿模、支撑关系错（灯挂在天花板下却没有吊杆） | 结构事实卡 + 支撑/接触检查（§3） |
| 材质工艺 | 全场上同一种「木头色」，读起来像塑料 | 材质分层表（§2.6）+ 材质参考 |
| 被遮挡的细节 | 前景一挪，后面是空的 | 遮挡链登记（§2.9），空白区必须显式声明 |
| 风格出处 | 只能模仿「像卡通」，抓不到具体的线条与色阶语言 | 风格检索：同流派背景美术 / 色指定表 |

**结论：参考图定「这一帧长什么样」，外部资料定「这个东西本来是什么样」。两者都缺，就只能做表面复刻。**

## 1. 三步走，三份产物

Stage 0 拆成三个子步骤，**三份都过门禁才准进 Stage 1**。顺序不可调换：
先描述（我看懂了什么）→ 再检索（世界上它是什么样）→ 最后拆解（怎么落到三维）。

| 子步 | 产物 | 回答的问题 | 门禁 |
|---|---|---|---|
| 0A 结构化描述 | `00-spec.md` | 我要还原的到底是哪些可判定的特征？ | 十段齐全 + RCI 表 ≥6 条 P0 |
| 0B 工程参考 | `00-refs.md` | 这些东西在现实/原作里是什么结构？ | ≥3 条 A/B 级来源 + 结构事实卡 ≥5 张 |
| 0C 拆解报告 | `00-analysis.md` | 怎么翻译成几何、色板、光照、相机？ | 原 Stage 0 门禁（不变） |

> 0B 不是「找图抄」，是找**结构事实**。抄不到的，写进【不确定项】并说明推断依据，
> 不许用「大概就是这样」糊过去。

## 2. 0A 结构化描述：十段模板

填不出的写「未知 + 推断依据 + 置信度（高/中/低）」，**不要留空，也不要编**。

### 2.1 主体（Subject）

| 字段 | 要求 | 判据 |
|---|---|---|
| 身份 | 一句话说清是什么，不写形容词 | 「操作台后一只橙红甲壳类，双螯前伸」而非「一个可爱的角色」 |
| 数量与朝向 | 逐个编号，标明面向相机的角度 | 「两只螯，左右各一，正面偏内 15°」 |
| 不可替代特征 | 去掉就不再是它：3–5 条 | 螯的分瓣钳形、外凸眼柄、台面上堆叠的矩形票券 |
| 可变特征 | 可以简化而不伤害识别度 | 票券上的纹样、木纹走向 |
| 尺度锚点 | 用画面内已知物做基准 | 以桌面宽 1.6m 为 1 单位 |

**判据**：把「不可替代特征」单独拿给别人看，对方能说出这是什么场景 → 合格。

### 2.2 构图（Composition）

- 画幅比、九宫格落位、主体包围盒（宽/高百分比、中心 cx/cy）。
- 地平线 / 墙地交界 / 桌面远边 / 主体基线，四条水平线各在画面高度的百分比。
- 透视类型：单点 / 两点 / 三点；消失点屏幕坐标（单点透视要给出）。
- **相机反解**：视高、俯角、等效焦距。给出反解所用的约束点与残差，别只写结果。

> 四项水平线比「主体占比」更稳，因为它不随主体缩放漂移。先定线，再定框。

### 2.3 风格（Style）

| 字段 | 选项 | 影响 |
|---|---|---|
| 线条语言 | 等粗硬线 / 起收笔变粗细 / 无描边靠色块 | 决定描边是否恒定像素宽 |
| 色阶数 | 2 / 3 / 4 / 5 阶，是否软过渡 | 决定 gradientMap 与 bandSoftness |
| 阴影硬度 | 硬边 / 半硬 / 柔和 | 决定是否开阴影贴图与半径 |
| 高光 | 无 / 硬高光块 / 渐变高光 | 决定用不用自定义 Shader |
| 质感颗粒 | 无 / 纸纹 / 胶片颗粒 | 决定后处理是否加 noise |
| 流派坐标 | 手绘 TV 动画 / 剧场版背景美术 / 欧美卡通风 / 日式赛璐璐 | 决定检索关键词与曲线密度 |

**判据**：能说出「这一帧属于哪一类」，而不是「卡通」。

### 2.4 色彩（Color）

- 语义区域色板表：`区域 | hex | 亮度 | 区域占比 | 用于哪个材质`。
- 至少覆盖：天空/上墙、下墙、地面、主体、前景、主道具、点缀色。
- 色相分布：主色相、辅助色相、对比色相各是什么，各自占比。
- 饱和度策略：整体中饱和还是高饱和；哪个物体是唯一的饱和高点。
- 明度结构：最暗 10%、中位、最亮 10% 三档分别落在什么材质上。
- 冷暖对立：暖光区 / 冷光区的分界在哪。

> 采样必须按语义区域分框（见 `visual-parity.md` G2），禁止全图 k-means 直接当基色。

### 2.5 光影（Lighting）

| 字段 | 要求 |
|---|---|
| 主光 | 钟点方位 + 仰角 + 色温（K 或暖/中性/冷）+ 是否为可见光源 |
| 补光 | 方位 + 强度比（相对主光）+ 冷暖 |
| 轮廓光 | 有/无，哪一侧，宽度 |
| 阴影 | 方向（与主光夹角容差 ≤15°）、硬度、是否落地 |
| 明暗比 | 受光面 / 背光面的亮度差（亮度单位） |
| 环境遮蔽 | 哪些缝隙明显变暗（桌下、柜后、梁下） |
| 光斑与辉光 | 有无镜头溢光、墙面上是否有光斑（离墙距离要记） |

### 2.6 材质（Material）

逐个主道具填，**不许全场上同一种材质**：

```
物体 | 材质类别 | 固有色 | 粗糙度倾向（哑光/半哑/亮） | 是否有高光 | 纹理密度（无/低/中/高） | 边缘处理（新/磨损/包边）
```

材质类别限定在：木（原木/漆木/深色木）、布（绒/帆布/呢）、金属（黄铜/钢/铁）、玻璃、纸、皮革、石、漆。

> 只写颜色不写粗糙度，到 Stage 3 会全场一个手感 —— 这是「像塑料」的根因。

### 2.7 比例（Proportion）

- 以 1.7m 人高为默认基准（无人物时用门高 2.0m 或桌高 0.75m 反推）。
- 列出尺度链：地面 → 桌高 → 桌面 → 主体 → 头顶 → 天花板，每段给米数。
- 列出画面内关键比值：桌宽/桌高、椅背高/桌高、画框宽/墙宽、舷窗直径/墙高。
- **透视自洽检查**：同一水平面上的平行线是否收敛到同一消失点；桌沿与墙脚线的上下关系是否符合相机高度。

### 2.8 关键细节（Key Details）

10–20 条，按「一眼能不能认出这个场景」排序，标优先级：

| 级别 | 定义 | 数量要求 |
|---|---|---|
| P0 | 缺了就判「不是这个场景」 | 3–6 条 |
| P1 | 缺了明显掉档，但不致命 | 5–10 条 |
| P2 | 加分项，可程序化生成 | 不限 |

每条写成「物体 + 可判定的形态」，不写感受：
「宝箱盖是半圆弧，弧顶高出箱体 0.15 倍箱宽」而不是「宝箱很有质感」。

### 2.9 空间层次与遮挡链（Depth & Occlusion）

- 前景 / 中景 / 远景各列物体清单，标大致距离（米）。
- 遮挡链写成 `A 遮 B 遮 C`，逐条编号；**每一条都要在 Stage 2 复核**。
- 显式声明「参考图里看不到的部分」：背面墙、桌子下方、柜子后面。
  这些位置要么补建（用同语汇），要么在交互里锁死不可见 —— 二选一，不许默认忽略。

### 2.10 叙事与不确定项

- 时段、天气、情绪、画面在讲什么事（一句话）。
- 【不确定项】逐条：`字段 | 推断值 | 依据 | 置信度 | 若错了会怎样`。

## 3. 0B 工程参考检索：从「像」到「对」

### 3.1 检索目标只有三类

| 类型 | 要找什么 | 用途 |
|---|---|---|
| 结构参考 | 同一主体的多角度图、正侧背三视图、剖面、爆炸图、尺寸标注 | 补背面/侧面/连接方式，定尺度链 |
| 材质参考 | 同类材质的真实照片（新/旧两态）、工艺细节特写 | 定粗糙度、纹理密度、边缘磨损 |
| 风格参考 | 同流派背景美术、色指定表、layout 构图稿 | 定线条语言、色阶数、色彩结构 |

### 3.2 检索词构造公式

| 目标 | 公式 | 示例 |
|---|---|---|
| 多角度 | `<subject> turnaround sheet` / `<subject> orthographic front side back` | `crab claw turnaround reference` |
| 工程尺寸 | `<object> blueprint dimensions` / `<object> exploded view` | `wooden desk exploded view dimensions` |
| 材质 | `<material> material reference` / `<material> texture breakdown` | `brass patina material reference` |
| 风格 | `<studio/film> background art` / `<style> color script` | `<film> background art layout` |
| 实物验证 | `<object> real life photo` / `<object> museum` | `vintage brass porthole photo` |

同时检索中英文两版：中文源常有一手实物图，英文源常有设定集扫描。

### 3.3 采信分级：只有 A/B 能进几何决策

| 级别 | 定义 | 可否支撑几何/材质决策 |
|---|---|---|
| A | 官方设定集、出品方公开素材、厂商工程图、博物馆藏品图、多角度实物照 | 可 |
| B | 百科条目、模型站三视图、专业教程、拆解测评、图纸站 | 可（需两条以上互证） |
| C | 论坛讨论、单张截图、二手转述、AI 生成图 | **不可**，只能写进【不确定项】 |

**A 级单条即可用；B 级需两条互证；C 级一律不用。** 找不到 A/B 就如实写「未获得可靠结构参考，按常识补建」。

### 3.4 结构事实卡（每张卡只写一件事）

```markdown
### F3 · 螯钳的开合结构
- 来源: <URL>（A 级，访问 2026-11-11）
- 事实: 螯由不动指与可动指两瓣组成，铰接在近端；闭合时两指贴合，钳口呈楔形缝隙
- 用于: Stage 2 护手轮廓比例（两瓣约 6:4）、Stage 3 描边走向（缝隙处不断线）
- 与参考图冲突: 参考图把螯画成心形，属风格化夸张
  → 轮廓跟参考图，**结构跟事实卡**（保留铰接缝，不做整块实心）
```

**冲突处理原则**：形态服从参考图（这是风格），结构服从事实（这是合理性）。
两者冲突时在卡片里写清「哪一层服从谁」，不要含糊。

### 3.5 尺寸反推表

检索到的真实尺寸直接写进表里，Stage 2 用它校核：

```
物体 | 检索到的真实尺寸 | 本场景取值 | 依据/来源 | 偏差理由
```

一条都没有 → 说明检索失败，必须在 `00-refs.md` 顶部写明「无尺寸参考，全部按比例推算」。

### 3.6 版权与 IP 边界

- **可借鉴**：结构关系、连接方式、材质工艺、物理尺寸、透视规律 —— 这些是工程事实。
- **不可复制**：角色造型、标志性纹样、成套配色方案、可识别的 Logo 与文字。
- 检索到的商用素材**不得下载使用**（R4 仍然生效：全部程序化生成）。
- 在 `00-refs.md` 末尾写一句边界声明：本次借用的是哪些结构事实，抽象掉了哪些造型特征。

## 4. 0A/0B 的合成产物：RCI 参考修正项

RCI（Reference Correction Item）= 一条**可以被判定通过或不通过**的还原要求。
它是 Stage 1 的输入、Stage 2/3/5/9 的验收清单，也是返工时的定位依据。

### 4.1 表格格式（固定七列，不许省）

| ID | 类别 | 修正项 | 期望值 / 形态 | 校验方法 | 校验阶段 | 状态 |
|---|---|---|---|---|---|---|
| R01 | G 构图 | 主体中心 | cx 0.533 / cy 0.732 | 逐顶点投影 measureFrame | 2,7,9 | PASS |
| R02 | C 色彩 | 桌面区钞票绿占比 | 22% ±9pt | 像素分割脚本 | 2,3,5,9 | PASS |
| R03 | S 结构 | 吊灯有吊杆连接天花板 | 可见杆件，无悬空 | 看图判据：灯体上方必须有连续杆件到顶 | 2,9 | PASS |
| R04 | D 细节 | 宝箱盖为半圆弧 | 弧顶高出箱体 ≥0.15 箱宽 | 源码：该物体使用 Shape/圆弧构造 | 3 | PASS |

### 4.2 硬性要求

1. **≥6 条 P0**，覆盖 G/C/L/M/S/D 六类各至少一条。
2. 「校验方法」只能从下表中选，且必须写清**怎么判**：

| 方法 | 适用 | 写法要求 |
|---|---|---|
| 像素统计 | 颜色占比、亮度分布、过曝/死黑 | 给出区域框 + 阈值 + 命令（parity-check.py） |
| 投影测量 | 包围盒、中心、地平线、遮挡 | 给出目标值 + 容差 + measureFrame |
| 源码计数 | 曲线构造次数、图元类别分布、材质数量 | 给出正则/统计口径 + 下限 |
| 看图判据 | 结构、细节、形态 | **必须写出「看到什么算 PASS、看到什么算 FAIL」** |
| 尺寸核验 | 尺度链、比例 | 给出米数 + 允许偏差（默认 ±8%） |

3. 「看图判据」是最弱的一档，同一张表里不得超过 40% —— 能在代码里量的，不要靠眼睛。
4. **RCI 只增不删**。返工后发现新的还原要求就追加；旧条目只允许改状态（PASS/FAIL/WAIVED），
   WAIVED 必须写理由。删条目等于抹掉历史，下一轮必然重犯。
5. Stage 1 的 CONFIG 必须能逐条指向 RCI：哪几个字段负责哪几条。指不上的 RCI 说明方案有缺口。

### 4.3 状态流转

`TODO → FAIL → PASS`，或 `TODO → WAIVED（写明理由与代价）`。
交付时全表不得有 TODO；WAIVED 条目必须在交付话术里列出来。

## 5. 结构合理性六查（Stage 2 与 Stage 9 各做一次）

「看起来像」不难，「站得住」才难。逐条查，任何一条不过都要改，不许用材质掩盖。

| # | 检查 | 判据 | 典型错误 |
|---|---|---|---|
| S1 | 支撑关系 | 每个物体都能指出「靠什么撑着/挂着」 | 灯悬在半空、画框浮在墙前 5cm |
| S2 | 接触点 | 底面/背面与支撑面贴合，缝隙 ≤2mm | 桌子上沿插进墙里、椅子腿陷进地板 |
| S3 | 尺度链 | 从地面到天花板逐段相加自洽，偏差 ≤8% | 桌高 0.9m 却配 0.45m 椅座（膝部放不下） |
| S4 | 透视一致 | 同一水平面的平行线收敛同一消失点 | 桌面用一点透视、地板用两点透视 |
| S5 | 遮挡一致 | 遮挡链无循环矛盾 | A 遮 B、B 遮 C、C 又遮 A |
| S6 | 物理合理 | 无穿透、无镜像反光方向错误、无重力异常 | 酒桶穿进柜体、玻璃反射光源方位相反 |

六查结果写成一行表：`S1 PASS / S2 PASS / S3 FAIL(桌高 0.90，应 0.75) / …`

## 7. 反模式

- **把描述写成观后感**：「很有氛围」「质感很好」——不可判定，等于没写。
- **只描述看得见的一面**：不写背面、不写桌下，Stage 7 一给交互就崩。
- **检索当抄图**：下载素材直接贴图 → 违反 R4，且风格立刻不统一。
- **用 C 级来源定结构**：论坛一句「大概三米高」就把尺度链带偏。
- **RCI 写成参数表**：`outline.px = 2` 是参数，不是修正项。修正项必须是「画面里应该看到什么」。
- **RCI 全用「看图判据」**：最后一整张表靠自觉，等于没有门禁。
- **删掉 FAIL 的历史条目**：下一轮同一处必然再错一次。
- **把参考图的画师错误当真**：透视线不自洽时，先记为【图本身不自洽】，按物理反解重定相机，
  并在文档写明偏离理由（已有实例：桌面远边画到墙脚线以下）。
