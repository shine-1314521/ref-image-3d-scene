# 各阶段门禁细则

按阶段查阅。每节结构固定：前置 → 要求 → 量化门禁 → 自检 → 失败处方 → 禁止。
门禁里的数字是**默认目标值**，参考图明确指向别的值时以参考图为准，但要在门禁块里写明「偏离理由」。

> **先读 `references/visual-parity.md`。** 下面各节的占比/色阶门禁只验证「包围盒与参数」，
> 不验证「画面内容」。已有一次真实事故：十阶段全过、占比五项全 PASS、控制台 0 报错，
> 成品仍被判「很差」——主体亮绿像素 0%（参考 22%），且全场只有 Box + Cylinder。
> 视觉对等六道闸门（G0 可见面 / G1 几何语言 / G2 语义色板 / G3 主体可见性 / G4 亮度分布 / G5 结构与细节）是**叠加在本文件之上的硬约束**，
> 任一 FAIL 不得交付。验收脚本：`assets/parity-check.py`（画面）+ `assets/rci-status.py`（规格书）。

## Stage 0 · 参考规格（0A 描述 / 0B 检索 / 0C 拆解）

**前置**：参考图或文字描述。
**产出**：`00-spec.md` → `00-refs.md` → `00-analysis.md`，三份都不含代码。
**方法**：完整模板与判据见 `references/reference-spec.md`，填空用 `assets/reference-spec-template.md`。

> 子步骤顺序不可调换：先写「我看懂了什么」（0A），再查「世界上它是什么样」（0B），
> 最后才翻译成「三维怎么搭」（0C）。反过来会先入为主，用检索去凑自己已有的结论。

### 0A 结构化描述（`00-spec.md`）

十段必须齐全：主体 / 构图 / 风格 / 色彩 / 光影 / 材质 / 比例 / 关键细节 / 空间层次 / 不确定项。
每段的字段与判据见 `reference-spec.md` §2。填不出的写「未知 | 推断依据 | 置信度」，不要留空、不要编。

三条最容易漏、且必须写：

```
【主体】不可替代特征 3–5 条（去掉就不再是它）+ 可简化特征（不伤识别度）
【色彩】语义区域色板表：区域 | hex | 亮度 | 区域占比 | 对应材质
【关键细节】P0 3–6 条 / P1 5–10 条，每条写成「物体 + 可判定的形态」
```

**RCI 表**（同一文件末尾）是 0A 的核心产物：≥6 条 P0，G/C/L/M/S/D 六类各 ≥1，
七列固定 `ID | 类别 | 修正项 | 期望值/形态 | 校验方法 | 校验阶段 | 状态`。
校验方法只能是「像素统计 / 投影测量 / 源码计数 / 看图判据 / 尺寸核验」，
其中「看图判据」必须写明看到什么算 PASS，且占比 ≤40%。

**门禁**：十段齐全；RCI ≥6 条 P0 且六类覆盖；不确定项每条都有置信度；用户能逐条说「对 / 改成 XX」。

### 0B 工程参考（`00-refs.md`）

检索三类目标：结构参考（多角度/三视图/剖面/爆炸图）、材质参考（同材质新旧两态）、风格参考（同流派背景美术/色指定）。
检索词公式、来源分级、事实卡格式见 `reference-spec.md` §3。

硬性要求：

1. **≥3 条 A/B 级来源**。A 级 = 官方设定集/厂商工程图/博物馆藏品/多角度实物照；B 级 = 百科、模型站三视图、专业教程、拆解测评（需两条互证）；C 级（论坛/单张截图/AI 生成图）**不得支撑几何决策**。
2. **≥5 张结构事实卡**，每张只写一件事：`来源（级别+URL+日期）| 事实 | 用于哪一阶段 | 与参考图冲突时哪层服从谁`。
3. **尺寸反推表**：`物体 | 检索真实尺寸 | 本场景取值 | 来源 | 偏差理由`。一条都没有 → 在文件顶部写「无尺寸参考，全部按比例推算」。
4. **冲突处理原则**：形态服从参考图（风格），结构服从事实（合理性），并在卡片里写清哪层服从谁。
5. **边界声明**：本次借用了哪些结构事实、抽象掉了哪些造型特征；不下载商用素材（R4 仍生效）。

**门禁**：≥3 条 A/B、≥5 张事实卡、尺寸表已填或已声明缺失、边界声明已写。
找不到 A/B 时如实写「未获得可靠结构参考，按常识补建」，并把相关 RCI 降级——不许假装查过。

### 0C 拆解报告（`00-analysis.md`）

把 0A/0B 翻译成可执行的渲染决策，按下列字段逐条填：

```
【构图】主体九宫格位置；包围盒宽/高百分比（5% 精度）；地平线百分比；
       透视类型（单点/两点）；消失点屏幕坐标；四条水平线（地平线/墙地交界/桌面远边/主体基线）
【空间层次】前景/中景/远景各是什么；遮挡链编号；每层最近/最远距离比；需补建或锁死的区域
【主体】名称、几何构成、数量、朝向；不可替代特征对应的几何手段
【几何语言】逐个列出圆角/弧线/旋转体特征（物体名 + 曲线类型），
       给出「曲线物体 / 全部物体」比例；手绘卡通默认 ≥60%
【环境】天空类型、地面或水面、远景山体或建筑
【光源】主光方位（钟点 + 仰角）、色温、补光侧、有无轮廓光
【色板】5–7 个 hex + 用途，来自 0A 的语义区域表，禁止全图 k-means 直接当基色
【材质】按类别分层：木/布/金属/玻璃/纸/漆，各给粗糙度倾向与纹理密度
【比例】尺度链（地面→桌→主体→顶→天花板，米制）+ 关键比值 + 透视自洽检查
【内容可见性】主体区域「主体特征色像素占比」与「前景特征色像素占比」两个基线
【风格特征】描边粗细、阴影硬度、辉光、颗粒、色阶数量
【画面占比基线】主体 cx、cy、宽占比、高占比、地平线 y
【不确定项】继承 0A，并补 0B 未解决的项
```

拍平透视：照片类参考图额外写一段「动漫化转译」——抽哪 5 个色、几何简化到什么程度、丢掉哪些高频细节。

**门禁**：以下三项齐全，缺一不进 Stage 1：
1. 语义区域色板表（覆盖上墙/下墙/地面/主体/前景/主道具）；
2. 【几何语言】清单与曲线物体比例；
3. 【内容可见性】两个百分比基线。
外加：RCI 每条都能指出「由哪一条拆解结论支撑」，指不上的回 0A 补。

### 禁止

写代码、写 CONFIG、猜材质参数、凭印象补结构。
跳过 0A 直接写 0C（没有可判定项就无从验收），或跳过 0B 直接用单张图定背面与连接方式。

## Stage 1 · 技术方案与参数表

**前置**：Stage 0 确认。
**产出**：`01-config.md`（CONFIG 草案 + 选型说明），仍不含可运行代码。

### 要求

1. 输出完整 CONFIG 草案，字段定义见 `references/config-reference.md`。
2. 说明三项选型，每项给结论 + 一句理由：
   - 着色：`MeshToonMaterial` + gradientMap（默认）还是自定义 Shader（需要轮廓光/多层色阶时）。**默认选前者**，能覆盖 90% 场景。
   - 描边：Inverted Hull（默认，性能好、可控）还是 `OutlinePass`（几何复杂、硬边多时更稳）。两者不可混用于同一物体。
   - 后处理链：`RenderPass → UnrealBloomPass → GradePass → OutputPass`。说明为什么 Grade 在 Bloom 之后（先发光再统一调色，避免辉光被调色削掉）。
3. 列出降级开关：`toon.outline.enabled`、`post.bloom.strength`、`light.shadow.enabled`、`perf.*`，并说明各自关掉后画面损失什么。
4. **RCI → CONFIG 映射表**：`00-spec.md` 里每条 P0 修正项，都要指出由哪几个字段负责兑现
   （例：`R01 → camera.target / subject.position`，`R04 → palette.money`）。
   指不上任何字段的 RCI，说明方案有缺口，回 Stage 0 补或在本阶段补方案。
5. 尺度链落表：`00-spec.md` §7 的米制数值直接进 CONFIG 或几何常量，正文不得再出现凭空的尺寸。

### 门禁

用户确认色板 hex 与描边方案。这两项返工成本最高，必须先钉死。
**映射表必须无空项** —— 每条 P0 都有归属，否则 Stage 9 一定有几条 RCI 无法收口。

### 失败处方

- 用户说「说不上来但不像」→ 回到 Stage 0 重取色，用取色器逐点采样，不要靠记忆。
- 色板给了 10 个色 → 砍到 7 个以内，多余的交由光照与调色生成。
- 色板是全图 k-means 跑出来的 → 作废，改按语义区域分框聚类。全图主色只能判断色调倾向，
  不能给具体材质上色；照抄会让墙/地/道具整体发黑（实测低 60+ 亮度单位）。
- 用户说「没有曲线 / 都是几何图形拼接」→ 这不是调参问题，回 Stage 0 补【几何语言】，
  并在 Stage 1 的选型说明里新增第四项「曲线几何方案」（Shape / Lathe / Tube 各覆盖哪些物体）。

## Stage 2 · 白模构图

**前置**：Stage 1 确认。
**产出**：`02-blockout.html`，可旋转查看的灰模。

### 要求

- 材质统一 `MeshStandardMaterial`（`color: 0x9aa0a6`，`roughness: 1`，`metalness: 0`）或 `MeshLambertMaterial`。
- 保留一盏方向光 + 一盏环境光，开阴影，能看出体积与投影方向。
- 相机 `fov / position / target` 严格取 CONFIG，不得为了「好看」偷改。
- **先写锁定清单，再动相机**：`LOCK-n`（受接触/叙事/刚性约束、不允许动的项）与 `FREE-n`（可动的项）。
  构图只允许动 `FREE`。写不出锁定清单说明还没弄清场景物理，此时调构图必然返工。
  方法与推演见 `camera-and-assembly.md` §1。
- **朝向可见性（R11）**：主体的不可替代特征——钳口缝、正脸、门洞开口——必须在默认机位可见。
  看不到时先做单轴 A/B 实验定朝向，**禁止此时改轮廓控制点**。
  判据：把该特征的形态单独描述一遍，能在截图上指出来在哪；指不出即 FAIL。
- 几何只用基本体，允许轻微不规则（缩放/旋转），不允许雕刻细节。
  **但若 Stage 0 判定为手绘曲线风格，白模就要用圆角基本体占位**（圆角盒 / 旋转体 / 管），
  不能整场直角 Box。几何语言错了到 Stage 3 才发现，返工成本翻倍。
- 打开量化测帧 HUD（见 `threejs-recipes.md` 的 `measureFrame`），实时显示主体占屏比。
  `measureFrame` 必须投影**实际网格顶点**，不得用 `Box3` 的 8 个角点：
  第一人称伸向镜头的物体会把近角撑出画面（实测报 w=1.049），
  逼得后续用整体非等比缩放凑数字，最终主体被压没。

### 量化门禁

对照 Stage 0 的【画面占比基线】：

| 项 | 容差 |
|---|---|
| 主体包围盒宽占比 | ±5%（绝对值） |
| 主体中心 cx | ±4% 画面宽 |
| 主体中心 cy | ±4% 画面高 |
| 地平线 y | ±3% 画面高 |
| 前后景遮挡关系 | 必须正确，无容差 |
| **主体特征色像素占比** | 与 Stage 0 基线偏差 ≤9 个百分点 |
| **前景特征色像素占比** | 与 Stage 0 基线偏差 ≤9 个百分点 |

任一项超差 → 调相机或几何，不是调材质。

**主体特征色占比接近 0 时，即使上面四项全 PASS 也一律判 FAIL。**
占比门禁只保证包围盒位置，不保证主体没被前景吞掉 —— 这是已被实测证实的失效模式。
另外：构图只允许用**平移**和**单个物体的尺寸**调整；
禁止给主体组加非等比整体 `scale` 去凑占比（会压扁层次、把钞票压进桌后）。

**结构六查**（与占比门禁并列，任一 FAIL 不得进 Stage 3）：

| # | 判据 | 怎么查 |
|---|---|---|
| S1 支撑 | 每个物体能指出靠什么撑着/挂着 | 逐物体在清单里写支撑件；灯必须有杆到顶、画必须有挂钩或贴墙 |
| S2 接触 | 底面/背面与支撑面贴合，缝隙 ≤2mm | 打印物体底 y 与支撑面 y 的差值 |
| S3 尺度链 | 地面→桌→主体→顶→天花板逐段相加自洽，偏差 ≤8% | 对照 `00-spec.md` §7 |
| S4 透视 | 同一水平面平行线收敛同一消失点 | 投影两条边缘线，比较交点 |
| S5 遮挡 | 遮挡链无循环矛盾 | 对照 `00-spec.md` §9 逐条走一遍 |
| S6 物理 | 无穿透、无镜像反光方向错误 | 转 3 个视角各看一次 |

> 实测案例：吊灯吊杆只到 2.52m，天花板 3.03m，悬空 0.51m。
> 正视投影完全看不出来（杆细且顶端出画），转视角立刻露馅 —— 这就是 S1 存在的理由。

**装配自检**（多部件主体必做，白模阶段就要过；算法见 `camera-and-assembly.md`）：

| 项 | 判据 | 怎么量 |
|---|---|---|
| A1 组坐标系 | 复合主体有独立 Group，原点在底面中心，子件无世界坐标 | 搜源码：子件坐标里不得出现角色站位的绝对坐标 |
| A2 曲面附肢 | 根部与宿主表面间隙 ≤2mm，可见长度 ≥总长 30% | 该高度宿主半径（含 z 向缩放）× 对比根部坐标 |
| A3 贴片深度 | 挤出体上的装饰 z > `depth/2` | 逐个贴片核对 z 与所属挤出体的 depth |
| A4 接触保持 | 锁定项在相机绕一圈后仍接触 | 每 90° 拍一张，比对钳/脚是否仍贴合 |

> 实测案例：鼻子放在接近壳顶的高度，该处壳半径只有 0.15，整根埋在壳里，
> 屏幕上只剩一道描边折痕——A2 就是为了让这种「看不见的装配错误」变可量。

### 自检

- [ ] 主体位置与参考图同侧、同高度
- [ ] 主体占画面比例在容差内
- [ ] 地平线高度一致，没有倾斜（相机 up 未被动过）
- [ ] 前景不挡主体关键轮廓；远景确实在后
- [ ] 无悬空、无穿模、无比例失衡（人/树/石相对大小合理）
- [ ] 旋转一圈不出现空场景或几何背面

### 失败处方

| 现象 | 改什么 | 不要改什么 |
|---|---|---|
| 主体太大/太小 | `camera.position` 与 target 的距离（每 10% 偏差约调 12% 距离） | 物体尺寸 |
| 构图偏左右 | `camera.target.x`，或主体组整体位移 | FOV |
| 构图偏上下 | `camera.target.y` 与相机高度同调 | 地平线（会连带跑） |
| 层次扁平 | 拉开前/中景的 z 距离到 1.5 倍以上 | 相机 |
| 透视不对（广角压缩/长焦拉伸） | `camera.fov`（人眼感 40–50，广角 60–75） | 距离 |
| 主体被切边 | 先降 FOV 或加距离，再核占比 | 裁剪几何 |

### 禁止

Toon 材质、描边、后处理、粒子、任何 `palette` 里的颜色（除背景占位色）。

## Stage 3 · 赛璐璐材质与描边

**前置**：Stage 2 门禁通过。
**产出**：`03-toon.html`。

### 要求

1. **色阶贴图**：`DataTexture`，宽 = `toon.steps`（3–5），`NearestFilter`，`generateMipmaps = false`，`colorSpace = NoColorSpace`。三件缺一就会出现「渐变糊成一片」或「色阶偏白」。
2. **描边**：Inverted Hull。复制几何 → 删 uv → 生成平滑法线 → 沿法线在**视空间**外扩，
   外扩量乘以视距，得到屏幕空间近似恒定的线宽。
   **平滑法线按几何类型分两种**（2026-11-11 修订，原「一律 mergeVertices」是错的）：
   - Box / Cylinder 等硬边几何：删 uv → `mergeVertices` → `computeVertexNormals()`；
   - `ExtrudeGeometry` / `LatheGeometry` / `TubeGeometry` 等曲线几何：
     改用**径向法线**，即把每个顶点的法线替换为 `(position - 包围球中心).normalize()`。
     曲线几何做 mergeVertices 会让正面与侧面法线在圆角接缝互相抵消，
     描边裂成一圈锯齿状虚线（放大可见点状断点）。
3. **描边宽度用像素表达**，不要用世界单位。换算：`worldWidth ≈ px * 2 * tan(fov/2) / viewportHeight`。1080p、fov 45 时，1px ≈ 0.00077 世界单位/单位距离。原稿的 `0.02` 在这一换算下约 26px，是「黑框」而不是「描边」。
4. **阴影偏冷**：靠 `HemisphereLight` 的天空色（冷）+ 色阶最低阶略偏蓝实现，不要给阴影单独上色（平行光的阴影本身无颜色）。
5. **远处描边变细**：外扩量乘视距已经天然实现；如需更强衰减，加 `smoothstep(fadeStart, fadeEnd, dist)` 乘子。
6. **曲线几何最小集**：手绘卡通参考图必须至少用上
   `Shape + ExtrudeGeometry`（圆角盒/自定义轮廓）、`LatheGeometry`（旋转体）、
   `TubeGeometry`（空间曲线）、`TorusGeometry`（环）中的三类，
   覆盖 Stage 0【几何语言】清单里 ≥60% 的曲线物体。配方见 `visual-parity.md` 第 3 节。
   只做「把所有 Box 换成圆角盒」仍不够 —— 椅背弧线、桶身鼓形、缆绳这些必须用轮廓/旋转体/管。

### 量化门禁

- 1080p 下主景描边 1.5–2.5px；远景描边 ≤ 近景的 60%。
- 色阶台阶肉眼可见：沿受光面横向扫一条线，明暗跳变 ≥3 次。
- 描边无断裂、无三角形裂口（尤其立方体角、锥体接缝）。
- **源码中曲线几何构造调用次数 ≥12**（由 `assets/parity-check.py` 统计）。
- **色板落地后语义区域亮度与参考图差 ≤22**，且色阶最低阶不得造成整片死黑。
- **材质类别数 ≥6**（木 / 布 / 金属 / 玻璃 / 纸 / 漆 / 皮 / 石 中取 6），
  且同一类别内至少分两档明度或粗糙度 —— 全场一个「木头色」是「像塑料」的根因。
- **P0 细节兑现率 100%、P1 ≥80%**：逐条对 `00-spec.md` §8，
  缺哪条要在门禁块写明「缺什么、为什么、能否补」。P0 缺一条不得进 Stage 4。

### 自检

- [ ] 阴影是硬边台阶，不是平滑渐变
- [ ] 描边粗细均匀，转角处不裂开
- [ ] 远处物体描边明显更细
- [ ] 无「塑料高光」（Toon 本身无高光，出现即说明混入了 Standard 材质或环境贴图）
- [ ] 材质颜色与 `palette` 一致，未因色彩空间被二次转换

### 失败处方

| 现象 | 根因 | 处方 |
|---|---|---|
| 描边像一圈黑框 | 宽度按世界单位给的 | 改用像素换算（上公式），或乘 1/视距 |
| 立方体角上描边裂开 | 硬边几何的顶点法线不连续 | 删 uv → mergeVertices → computeVertexNormals（**仅硬边几何**） |
| 圆角/曲线物体描边成锯齿虚线 | Extrude 正面与侧面法线在接缝处抵消 | 改用径向法线，见上方要求 2 |
| 本想画一条金边，却生成一整片色块盖住主体 | `ExtrudeGeometry` 会把开放轮廓自动闭合并填充 | 细边一律用 `TubeGeometry` 沿轮廓走，或构造闭合环形 Shape（外轮廓 + 内孔） |
| 带贴图的圆角物体花纹错乱 | Extrude 的 UV 是 XY 世界单位而非 0–1 | 贴图交给标准 `BoxGeometry` 薄片，圆角只负责侧面体积 |
| 色阶看不出台阶 | gradientMap 用了线性过滤，或步数过多 | `NearestFilter`，步数降到 3–4 |
| 材质发灰发白 | 贴图 `colorSpace` 被当成 sRGB 二次线性化 | 设 `NoColorSpace` |
| 整体偏暗 | 色阶最低阶给到 0.05 以下 | 最低阶抬到 0.15–0.2 |
| 描边在薄片（花瓣/旗帜）上消失 | BackSide 在双面几何上翻面 | 薄片改用双面材质 + 顶点法线外扩，或改 OutlinePass |

### 禁止

Bloom、雾、粒子、天空渐变（Stage 4 才做）。此阶段背景用纯色即可。

## Stage 4 · 光照与天空氛围

**前置**：Stage 3 确认。
**产出**：`04-light-sky.html`。

### 要求

1. **主光**：`DirectionalLight`，方向取 `light.sunDir`，颜色取 `palette.mainLight`，开阴影。阴影相机范围贴合场景，不要用默认 ±5（会截断）或 ±500（精度浪费）。
2. **补光**：`HemisphereLight`（天空色冷、地面色暖、强度 0.4–0.8）+ 可选低强度 `AmbientLight`。补光只负责「暗部不死黑 + 偏冷」，不要用它提亮主光面。
3. **天空**：ShaderMaterial 球体，3–4 段色阶（`smoothstep` 分段，`bandSoftness` 控制过渡宽度），`side: BackSide`、`depthWrite: false`、`fog: false`（ShaderMaterial 默认不吃雾，但显式声明避免后人改动踩坑）。
4. **雾**：`FogExp2`，颜色取天空**底部**色，不要取中段色。雾会把远景压向天空色，形成纵深。
5. 可选：低角度主光 + 半透明锥体做丁达尔光，仅当参考图有明确光束时加。

### 量化门禁

- 阴影方向与参考图夹角 ≤15°。
- 除太阳本体外，画面最亮像素 ≤0.98（用取色器查，出现 255,255,255 即过曝）。
- 远景物体与天空色差 <8%（雾生效的判据）；远景出现硬边说明雾太淡或未开。
- 天空至少 3 段可辨识色带，不是一路平滑渐变。

### 自检

- [ ] 阴影朝向与参考图一致
- [ ] 天空分段、有动画摄影感
- [ ] 远山/建筑被雾自然吞掉，没有硬边
- [ ] 无过曝白块，暗部保留细节
- [ ] 天空球未被雾或 Bloom 影响（边缘无异常发亮）

### 失败处方

| 现象 | 处方 |
|---|---|
| 整体偏灰 | 主光强度 +30%，环境光 −40%；先调比值不要一起提 |
| 阴影脏黑 | 提高 Hemisphere 天空色强度，或把阴影侧材质色阶最低阶抬到 0.2 并偏蓝 |
| 天空太平 | 分段从 2 段改 3 段，`bandSoftness` 降到 0.03；加极轻噪点（±0.01）破带状 |
| 远景边缘像剪纸 | 雾密度 ×1.5，或雾色改为天空底部色 |
| 地面亮得发白 | 检查地面材质色是否已接近 1.0；Toon 下漫反射色上限建议 ≤0.85 |

### 禁止

Bloom、调色、粒子。此阶段只用「光 + 天空 + 雾」解释画面。

## Stage 5 · 后处理与色彩分级

**前置**：Stage 4 确认。
**产出**：`05-post.html`。

### 要求

1. 链路固定：`RenderPass → UnrealBloomPass → GradePass(ShaftPass) → OutputPass`。`OutputPass` 必须是最后一个，负责线性 → sRGB 的唯一一次转换。
2. **只做一次色彩空间转换**：`renderer.outputColorSpace = SRGBColorSpace`，`OutputPass` 内部按此转换；**禁止**在 GradePass 里手写 `pow(color, 1/2.2)`。
3. **GradePass 在线性空间做**：饱和度、对比（绕中灰 0.18）、阴影染冷/亮部染暖（按亮度 mix 两个 tint）、暗角（可合并进同一 pass，省一次全屏采样）。
4. Bloom 参数：`strength 0.4–0.8`、`radius 0.3–0.5`、`threshold 0.8–0.9`。阈值低于 0.7 会让整个画面发光。
5. `toneMapping` 默认 `NoToneMapping`（保护色阶纯度）；只有高光大面积溢出时才换 `ACESFilmicToneMapping` 并把 `exposure` 降到 0.9。

### 量化门禁

- Bloom 覆盖面积 <8% 画面（截图目测估算，或对阈值分割计数）。
- 暗部最暗值 >0.03（不死黑）；亮部除太阳外无 255 纯白。
- 与参考图并排比对，主色相偏移不超过一个色相环档位（约 30°）。

### 自检

- [ ] 辉光柔和，仅亮部溢出，不是全屏泛白
- [ ] 高光带颜色倾向（暖黄/暖橙），不是纯白
- [ ] 暗部保留细节，不是一团死黑
- [ ] 整体色彩接近参考图，不是「滤镜感」压过原图
- [ ] 关闭后处理时画面仍成立（说明后处理是加分不是遮丑）

### 失败处方

| 现象 | 根因 | 处方 |
|---|---|---|
| 全屏发光 | threshold 太低 | 提到 0.85，必要时把发光物单独提亮 |
| 颜色发脏发绿 | 在线性空间做了 gamma 类运算，或重复转换 | 删掉手写 gamma，只保留 OutputPass |
| 加后处理后整体变暗 | 少了 OutputPass，或 toneMapping 被应用两次 | 补 OutputPass；确认 renderer 与 pass 不重复 tonemap |
| 暗角压死四角 | `vignette.amount` >0.5 | 降到 0.25–0.35，`softness` 加大 |
| 描边被 Bloom 糊散 | 描边色亮度高 | 描边色亮度压到 0.15 以下（深紫/深蓝） |

## Stage 6 · 动态细节与粒子

**前置**：Stage 5 确认。
**产出**：`06-motion.html`。

### 要求

1. **风摆**：顶点着色器里 `sin(uTime * speed + position.y * freq)` 主导 + 一个低频副振，幅度乘高度权重 `smoothstep(0, h, position.y)`，保证根部不动。
2. **粒子**：`Points` + Canvas 程序化贴图（花瓣/萤火虫/雪）。`sizeAttenuation: true`、`depthWrite: false`、`alphaTest: 0.02`。
3. **萤火虫类**带呼吸明暗：`opacity = 0.4 + 0.6 * (0.5 + 0.5 * sin(t * 1.7 + phase))`。
4. 粒子速度与风向一致，不要上下乱飘；越过下界后回收复用，不要每帧新建对象。

### 量化门禁

- 数量：桌面 ≤400，移动 ≤150。
- 粒子在主体中心区域的遮挡率 <40%（用一个临时矩形估算即可）。
- 帧率下降 ≤10%（对比 Stage 5）。

### 自检

- [ ] 风摆自然，有相位差，不是整体机械抖动
- [ ] 粒子数量不抢主体
- [ ] 粒子没有被 Bloom 糊成一片光斑
- [ ] 移动端帧率不明显下降

### 失败处方

| 现象 | 处方 |
|---|---|
| 像被人摇树 | 给每个物体加随机相位/频率偏移，幅度降到 0.6 倍 |
| 粒子像雪花贴纸 | 加轻微自转 + 侧向漂移 + 大小随机（0.7–1.3 倍） |
| 一片糊白 | 粒子贴图 alpha 边缘过硬或颜色过亮；降到 0.8 亮度并减小 size |
| 根部在动 | 高度权重漏了，或权重下限不是 0 |

## Stage 7 · 交互与相机运动

**前置**：Stage 6 确认。
**产出**：`07-interaction.html`。

### 要求

1. `OrbitControls`：`enableDamping = true`、`dampingFactor 0.06–0.1`、`minDistance / maxDistance` 限制、`maxPolarAngle` 防钻地、`enablePan = false`（场景观看器默认不给平移，避免用户把主体推出画面）。
2. **视差**：指针归一化后做 lerp，作用在「世界组」而非相机（OrbitControls 每帧会覆写相机位姿，直接改相机会打架）。幅度 ≤0.15 世界单位。
3. **空闲自动环绕**：用户操作时暂停，停止操作 3s 后恢复；`autoRotateSpeed 0.1–0.3`。
4. 移动端触控天然由 OrbitControls 接管，需额外设 `touch-action: none` 防止页面滚动。
5. **限位必须由几何反推，不许拍脑袋**（R12），三条都要满足：
   - 方位限位相对初始朝向：`AZ0 = atan2(cam.x - target.x, cam.z - target.z)`，写 `AZ0 ± limit`。
     写绝对值会把机位硬拽到房间正面。
   - 极角下限随距离动态：`minPolar = max(设定值, acos((ceilY - target.y) / L))`。
     固定值必然二选一：近处不能俯看，或远处穿顶。
   - 距离上限受墙距约束：`maxDistance × sin(limit) ≤ 到该侧墙的距离 − 余量`。
     实测反例：`4.90 × sin(1.46) ≈ 4.85` 而前墙在 3.65，一转到底就穿出去。
6. **全周环视写 `±Infinity`，不能写 `±Math.PI`**：OrbitControls 把传入值折回 `[-π, π]`，
   `±π` 折成同一个数后命中 `min === max` 分支，方位被锁死——比限位更糟。
7. **墙体与障碍用射线收缩，不用硬 clamp**：沿 `target → camera` 求最近交点，把相机整体推近
   （保持极角）。硬 clamp 会让相机贴墙滑、方位被悄悄改掉，拖起来像「被墙吸住」。
   障碍用「xz 圆 + 顶高」近似，相机高于顶高可从上飞过。完整实现见 `camera-and-assembly.md` §6。

### 量化门禁

- 阻尼后停止拖拽，相机在 0.5s 内平滑停下，无回弹。
- 视差位移 ≤2% 画面宽度。
- 全程相机不进入任何几何体内部（绕一圈检查）。
- **6 组极位穷举**（方位 min/max/mid × 极角 min/max × 距离 min/max），逐个截图，
  每张只查三件事：大面积单色、暴露的物体内壁、主体被切断。表格见 `camera-and-assembly.md` §6.6。
- **相机坐标用探针核对**，不靠肉眼判断「大概没穿墙」：
  `document.title = camera.position.toArray()` 配合 `--dump-dom` 读回数值。
- **补建面检查**：转到极角/方位角两端各停 1 帧，`00-spec.md` §9 里「需补建或锁死」的
  区域不得出现空洞、破面或纯背景色。锁死的方位必须在 `maxAzimuthAngle` 里真的锁住。
- **可见面重估（R14）**：若相对 Stage 2 方位改 >15° 或俯仰改 >10°，必须重跑 360° 可见面清点，
  新进入视野的区间逐个确认「有几何」或「有意遮挡」。换成第三人称后发现 +z 是一面空墙，
  就是漏了这一步。

### 自检

- [ ] 相机不穿模、不穿地
- [ ] 阻尼顺滑，不抖不振
- [ ] 视差克制，长时间看不晕
- [ ] 触控可用，页面不跟着滚动
- [ ] 转到背面/桌下不露空（补建面已做，或角度已锁死）

## Stage 8 · 性能与响应式

**前置**：Stage 7 确认。
**产出**：`08-perf.html`。
