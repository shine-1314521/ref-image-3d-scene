# 装配与相机：约束、坐标系、附肢、可达域

> 2026-11-13 一次完整第三人称返工后新增。那一轮有四个失败都发生在这里：
> ① 钳口朝向背离相机，却在轮廓控制点上盲调三轮；
> ② 鼻子整根埋进壳里，只剩一道描边折痕；
> ③ 给挤出体加的顶面高光 z 落在实体内部，从未被渲染过；
> ④ 相机距离拉满 + 方位打满时穿出前墙。
>
> 这四件事的共同点：**都不是调参能解决的，是「先把几何关系算清楚」的问题**。
> 本文件解决「东西怎么接、相机能去哪」；画面怎么验见 `visual-parity.md`。

---

## 1. 约束先行：哪些东西是被锁死的

构图之前先写一张锁定清单。**锁定项是常量，构图只允许动相机和未锁定物体。**

| 约束类型 | 判定问题 | 典型例子 | 锁定了什么 |
|---|---|---|---|
| 接触约束 | 这个物体靠什么保持住位置？ | 钳子压在钱堆上 | 角色的位置与朝向 |
| 叙事约束 | 少了这个姿态，画面还成立吗？ | 老板必须盯着钱 | 头部/瞳孔的朝向区间 |
| 支撑约束 | 谁撑着它？ | 吊灯靠吊杆吊在天花板 | 灯体的 x/z 与长度 |
| 接口约束 | 两个零件必须在同一轴线上？ | 眼柄必须从壳顶长出 | 眼柄根部与壳的连接点 |
| 刚性约束 | 转动会破坏哪个接触？ | 角色转身 → 钳子离桌 | 角色的 yaw 自由度 |

### 1.1 约束推演（真实案例）

需求是「第三人称，能看见角色」。直觉做法是「把相机放到角色背后」，但：

```
钳子压在桌面上（接触约束）
  → 钳子挂在角色组下（刚性约束）
    → 角色一旦 yaw 转身，钳子沿圆弧扫离桌面
      → 接触破坏，画面读成「两只钳子飘在桌上」
```

结论：**角色的朝向不是自由变量**，只能面向桌子。于是机位只剩两类：

| 机位 | 能看到 | 代价 |
|---|---|---|
| 隔桌对面（略高于眼柄） | 正脸、双钳、桌面钞票 | 前景被桌子占据；需要补「相机背后的那面墙」 |
| 侧后 55° | 剪影、背部轮廓 | 看不到表情；钳口朝向背对相机，识别度崩 |

选前者。代价是必须补建第四面墙（R14），这是选机位时就该预见的，不是做完才发现。

### 1.2 锁定清单写成什么样

```
LOCK-1 钳子（左右）底面与钱堆顶面贴合，缝宽 ≤2mm   → 角色 z 与 yaw 锁定
LOCK-2 角色面向 -z（桌子方向）                      → yaw = 0，不可调
LOCK-3 双钳一低一高（近侧压桌、远侧抬手）            → 钳的 lift 为常量
FREE-1 相机方位 / 极角 / 距离
FREE-2 墙面装饰、家具摆放
```

写不出这张表就说明还没弄清场景的物理，直接进 Stage 2 必然返工。

## 2. 朝向优先于轮廓（R11）

**主体的不可替代特征必须先在默认机位可见，再谈轮廓好不好看。**

失败实录：钳子开口被 `rotation.y = +side*0.62` 转到背对相机一侧，
屏幕上是一个闭合的圆面团。此时判断「掌部不够饱满」，
连调三轮 bezier 控制点——每一轮都在错误的投影上优化。

### 2.1 单轴 A/B 实验法

一次只改一个旋转轴，各拍一张，对比判据写死：

```js
// A：g.rotation.set(-0.10,  side * 0.55, -side * 0.10);
// B：g.rotation.set(-0.10, -side * 0.55, -side * 0.10);
```

| 症状 | 先怀疑哪个轴 | 判据 |
|---|---|---|
| 开口/缝完全看不见，物体像闭合实体 | `rotation.y`（偏航） | 缝的两条内缘是否同时可见 |
| 特征偏到画面一侧或朝下 | `rotation.z`（翻滚） | 特征中线是否过物体中心 |
| 只看到顶面/只看到侧面 | `rotation.x`（俯仰） | 正立面是否占投影面积一半以上 |
| 特征在但被自身遮挡 | 不是旋转，是**凹面深度**过度 | 收浅凹口，见 `visual-parity.md` §3 |

**判据必须写「看到什么算对」**，不许写「感觉好一些」。5 分钟能定案的事，别用三轮轮廓调参去猜。

### 2.2 朝向确定之后才允许做的事

- 调轮廓控制点（缝的开口宽度、掌/指比例）
- 加明暗（顶面高光、缝内暗带）
- 调挤出深度（厚度感）

顺序反了，后面全部白做。

## 3. 复合主体：局部坐标系

角色 / 机械 / 载具这类多部件主体，**必须先定组坐标系，再往里塞零件**。

### 3.1 约定

```
Group 原点 = 脚底中心（不是几何中心，不是世界原点）
Group 正面 = -z（与相机默认朝向一致）
所有子件坐标写在组内，禁止写世界坐标
改角色位置只动 group.position / rotation / scale
```

```js
const charGroup = new THREE.Group();
charGroup.position.set(CONFIG.scene.character.x, 0, CONFIG.scene.character.z);
charGroup.rotation.y = CONFIG.scene.character.yaw;
charGroup.scale.setScalar(CONFIG.scene.character.s);
world.add(charGroup);

// 螯/手部挂在角色节点下 —— 改一个 character.x 就能整体挪人，不用动任何子件坐标
const clawGroup = new THREE.Group();
charGroup.add(clawGroup);
```

### 3.2 为什么原点放脚底

| 原点位置 | 改 y 缩放时 | 改位置时 | 判断落地 |
|---|---|---|---|
| 脚底中心 | 从地面往上长，正确 | 直接就是站位 | 一眼可读（y=0 即地面） |
| 几何中心 | 上下同时撑开，会陷进地板 | 还要减半个身高 | 要额外记偏移量 |
| 世界原点 | 角色会飞走 | 无意义 | 不可读 |

### 3.3 反模式

- **钳子用世界坐标**：角色一转身，钳留在原地 → 画面读成「钳子飘在桌上」。这是本轮返工的起点。
- **每加一个零件就微调一次全局位置**：零件之间开始互相牵制，改 A 必崩 B。
- **缩放写在子件上而不是组上**：整体比例失去单一来源，改比例要改十几处。

## 4. 曲面附肢：先求宿主表面，再定根部

**贴附在旋转体上的附肢（鼻、柄、耳、角、把手），必须先算宿主曲面在该高度的位置与法向。**

### 4.1 失败实录

壳是 `LatheGeometry`，profile 最宽 0.34、前脸 z 向再乘 0.88。
鼻子根部放在 `y = 0.958`（接近壳顶）→ 该高度壳半径只有 0.15 左右，
管子整根被壳包住，屏幕上只剩一道描边折痕，看起来像「额头上有个凹坑」。

换到 `y = 0.905`（壳面最宽处往下收的位置）、根部外移到 `z = -0.225`，
管子朝前下方伸，尖端才真正穿出壳面。

### 4.2 算法

```js
// profile: [[r, y], …] 按 y 升序；scaleZ 是壳在 z 向的压扁系数
function radiusAt(profile, y) {
  for (let i = 1; i < profile.length; i++) {
    const [r0, y0] = profile[i - 1], [r1, y1] = profile[i];
    if (y <= y1) {
      const t = (y - y0) / Math.max(1e-6, y1 - y0);
      return r0 + (r1 - r0) * t;
    }
  }
  return profile[profile.length - 1][0];
}

// 附肢根部的 z 必须比「该高度壳面」再往外一个根部半径的量级
const rHost = radiusAt(shellProfile, yRoot) * shellScaleZ;
const zRoot = -(rHost - tailRadius * 0.55);   // 负号 = 朝 -z（正前方）
```

### 4.3 自检判据（三条，都能量）

| 判据 | 阈值 | 怎么量 |
|---|---|---|
| 附肢可见长度 | ≥ 总长 30% 在宿主曲面外 | 尖端到轴心的距离 − 该高度宿主半径 |
| 根部不悬空 | 根部与宿主表面间隙 ≤ 2mm | 根部 z − 宿主表面 z |
| 朝向符合参考图 | 与水平面夹角在参考图角度 ±15° | 尖端与根部连线 |

**别用「看起来在表面」判断**：旋转体的前脸凸度随高度剧变，越靠顶越往内收，
凭印象放的附肢十次有八次是埋进去的。

### 4.4 缩放要乘进去

`shell.scale.set(1, 1, 0.88)` 之后，z 向的实际半径是 `0.88 × profile 半径`。
忘记乘这个系数，附肢根部就会浮在壳外一小段——比埋进去更难查，因为看上去「差不多对」。

## 5. 挤出体的贴片：z 必须越过前表面

`ExtrudeGeometry` 的挤出体是**居中**的：`depth = 0.196` → 前表面在 `z = +0.098`。

于是这行代码：

```js
S(g, 0.072, 18, 12, 'clawLight', [x, y, 0.054], { … });   // 想加顶面高光
```

高光片的 z 是 0.054 < 0.098，**整片埋在实体内部，从未渲染出来**。
表现是「明明加了高光却还是平的」，然后继续怀疑光照和材质——其实它根本不存在。

### 5.1 规则

```js
const FRONT = depth / 2;          // 前表面 z
const DECAL_Z = FRONT + 0.004;    // 贴片必须比前表面再凸一点
```

| 做法 | 是否可靠 | 说明 |
|---|---|---|
| 贴片（球/圆柱压扁）放在 `front + ε` | 可靠 | 简单，适合高光块、暗带、花纹 |
| 用材质 `emissive` / 顶点色 | 可靠 | 不增加面，但需要 shader 或顶点属性 |
| 贴片放在 `front - ε` | **不可见** | 本轮踩的坑，且没有任何报错 |
| 贴片放在 0（几何中心平面） | **不可见** | 最常见的直觉错误 |

### 5.2 反过来利用它

挤出体的**后表面**在 `-depth/2`。如果想让某个细节只在背面可见（比如暗部、铭牌背面），
把它放在 `-depth/2 - ε` 是最省事的做法——但要在注释里写明，否则下一个人会以为是 bug。

## 6. 相机可达域

三件事都要算：**方位限位、极角下限、障碍与墙体**。

### 6.1 方位限位要相对初始朝向

`OrbitControls` 的 azimuth 是**世界角**，不是「相对当前机位」。
第三人称机位在桌子对面时，`AZ0 ≈ ±2.9 rad`，直接写 `min = -0.8` 会把相机硬拽到房间正面。

```js
const AZ0 = Math.atan2(camera.position.x - target.x, camera.position.z - target.z);
controls.minAzimuthAngle = AZ0 - CONFIG.camera.azimuthLimit;
controls.maxAzimuthAngle = AZ0 + CONFIG.camera.azimuthLimit;
```

**全周环视必须写 `±Infinity`，不能写 `±Math.PI`**：
`OrbitControls` 会把传入值折回 `[-π, π]`，`±π` 折成同一个数后命中 `min === max` 分支，
方位被锁死在一个角度上——比限位还糟。

### 6.2 极角下限随距离动态变化

固定 `minPolarAngle` 必然二选一：要么近处不能俯看，要么远处穿顶。

```js
const L = camera.position.distanceTo(target);
const cosMax = (ceilY - target.y) / Math.max(L, 0.2);   // ceilY = 天花板 - 余量
const phiMin = Math.acos(THREE.MathUtils.clamp(cosMax, -1, 1));
controls.minPolarAngle = Math.max(CONFIG.camera.minPolarAngle, phiMin);
```

### 6.3 距离上限由墙距反解

```
maxDistance × sin(方位限位) ≤ 到该侧墙的距离 − 余量
```

实测：`4.90 × sin(1.46) ≈ 4.85`，而前墙在 3.65 —— 一转到底就穿出去，只看到墙背面。

### 6.4 墙体与障碍：射线收缩，不要硬 clamp

硬 clamp `x/z` 的后果是相机**贴着墙继续滑**，方位被悄悄改掉，全景拖起来像「被墙吸住」。

正确做法：沿 `target → camera` 求最近交点，把相机整体推近到交点之前（保持极角）：

```js
const T = controls.target;
let px = camera.position.x - T.x, pz = camera.position.z - T.z;
let horiz = Math.hypot(px, pz);
if (horiz < 1e-4) { px = 0; pz = -1e-4; horiz = 1e-4; }
const ux = px / horiz, uz = pz / horiz;

let maxH = Infinity;
// 四面墙：按方向取对应的墙内边
if (Math.abs(ux) > 1e-4) maxH = Math.min(maxH, ((ux > 0 ? R.w/2 - 0.45 : -R.w/2 + 0.45) - T.x) / ux);
if (Math.abs(uz) > 1e-4) maxH = Math.min(maxH, ((uz > 0 ? R.d/2 - 0.55 : -R.d/2 + 0.90) - T.z) / uz);

// 柱状障碍：射线与圆求交，取进入圆的近根；target 已在圆内的跳过
for (const o of OBSTACLES) {
  if (camera.position.y > o.top + 0.10) continue;       // 高过顶面 → 从上方飞过
  const ox = o.x - T.x, oz = o.z - T.z;
  const proj = ox * ux + oz * uz;
  const perp2 = ox * ox + oz * oz - proj * proj;
  if (perp2 >= o.r * o.r) continue;
  const sEnter = proj - Math.sqrt(o.r * o.r - perp2);
  if (sEnter > 0.08 && sEnter < maxH) maxH = sEnter - 0.02;
}
maxH = Math.max(0.55, maxH);                            // 别把自己推穿 target

if (horiz > maxH) {
  const k = maxH / horiz;
  camera.position.set(T.x + px * k, T.y + (camera.position.y - T.y) * k, T.z + pz * k);
}
```

障碍用「xz 圆 + 顶高」近似即可：相机高于顶高就能从上方飞过，
所以桌子（0.70m）只在低机位生效，真正起作用的是灯柱 / 酒桶 / 椅子。

### 6.5 余量要按家具反推，不是拍的

```js
{ x: desk.x, z: desk.z, r: 1.40, top: desk.top }   // r 覆盖桌角，不是桌宽的一半
// 后墙余量 0.90：电视箱体伸到 z = -2.87，相机停在 -2.75 才不钻机壳
```

把余量的来源写成注释。下次改家具尺寸时，才知道哪里要跟着改。

### 6.6 极位穷举表（Stage 7 门禁）

六个组合覆盖全部边界，逐个截图，一张都不能省：

| # | 方位 | 极角 | 距离 | 查什么 |
|---|---|---|---|---|
| 1 | min | max | max | 贴墙 + 贴地 + 最远：是否穿墙/看到墙背面 |
| 2 | max | max | max | 另一侧同理 |
| 3 | mid | min | max | 最高机位 + 最远：是否穿天花板 |
| 4 | mid | max | min | 最近 + 最低：是否钻进地面或物体 |
| 5 | min | mid | mid | 侧向中距：家具是否正确遮挡 |
| 6 | max | mid | mid | 另一侧同理 |

判定用像素统计兜底：若某一机位的主色占比 >70% 且是墙的固有色，基本可判定「相机穿到墙外了」。
更可靠的判据是 `document.title = camera.position.toArray()` 探针，直接读出坐标对不对。

## 7. 机位变更 = 可见面重估（R14）

方位改 >15° 或俯仰改 >10°，可见面集合就变了。重估要回答一个问题：

**新进入视野的方位角区间，每个都能看到什么？**

| 新进入的方位 | 应看到 | 没有怎么办 |
|---|---|---|
| 相机背后的墙 | 墙面三段式 + 至少 2 个装饰 | 补建，用同语汇（不要凭空造风格） |
| 家具背面 | 有厚度、有背板 | 加背板，别留空壳 |
| 地板远端 | 地板延续 / 地毯 / 墙角线 | 补地板，或用地毯遮挡 |
| 天花板（低机位） | 有梁或灯 | 补梁，或把极角下限收紧 |

**先补几何，再调构图**。反过来会得到一个「构图对了但一转就穿帮」的场景。

## 8. 自检清单

- [ ] 锁定清单已写出（LOCK-n / FREE-n），构图只动了 FREE 项
- [ ] 主体的不可替代特征在默认机位可见（缝、开口、五官、正脸）
- [ ] 朝向做过单轴 A/B，两组截图有明确判据
- [ ] 复合主体有组坐标系，子件无世界坐标
- [ ] 曲面附肢的根部 z 与宿主表面差 ≤2mm，可见长度 ≥30%
- [ ] 所有挤出体贴片的 z > `depth/2`
- [ ] 方位限位相对 `AZ0`，全周模式写 `±Infinity`
- [ ] 极角下限随距离动态计算
- [ ] `maxDistance × sin(方位限位)` ≤ 到该侧墙的距离 − 余量
- [ ] 墙体与障碍用射线收缩，不用硬 clamp
- [ ] 6 组极位全部截图确认，相机坐标经探针核对
- [ ] 360° 可见面清点已完成，新进入视野的区间都有几何
